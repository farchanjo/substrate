# Privacy threat model

substrate runs as a local MCP server inside the developer's own trust boundary: an
MCP client spawns it on the operator's machine, it reads that machine's filesystem
and process table, and whatever it returns leaves the machine's boundary as soon
as the model forwards it. The data subjects are therefore the developer driving
the agent and the operator of the host: their files and file bytes, the command
lines and environment of their processes, the identity of their machine, and the
stdout/stderr of the children the agent spawns. The trust boundary is the MCP
transport — everything inside the substrate process is trusted, every tool
argument the model emits is not, and every response crosses back out. This
document is the LINDDUN counterpart to the STRIDE analysis in
[ADR-0029](../adr/0029-threat-model.md), whose attacker profile (a prompt-injected
payload, then a compromised local MCP client) it reuses unchanged; LINDDUN asks
the complementary question of how the system harms the privacy of the person whose
data it touches, not how an attacker harms the system. Rows that name no closing
control are marked residual rather than presented as covered.

| ID | Category | Threat | Affected Data | Mitigation |
|---|---|---|---|---|
| PT-001 | linking | Every tool call is joined to its session by `correlation_id` and to a client identity by `client_id`, so a log reader reconstructs one developer's whole working set from calls that are individually unidentifying. | `correlation_id`, `workflow_id`, `client_id`, `seq` on every audit event | One UUIDv7 is minted per call at the adapter entry point, and ids are scoped to a single server process lifetime, so cross-session linking is not implicit. The bounded label set is declared in the observability strategy ([observability.md](../observability/observability.md), [ADR-0038](../adr/0038-audit-event-semantics.md)). |
| PT-002 | linking | The launch trust store is a durable user-scope file that accumulates the absolute path of every blessed profile, so one file tells a local reader which projects the developer works on. | `~/.config/substrate/launch-trust.toml`: canonical profile paths, inode identity, `blessed_at` | The store must be mode `0600`; a looser mode is rejected with `LaunchError::TrustStoreInsecure` before any lookup proceeds, and appends are atomic ([ADR-0064](../adr/0064-launch-profile-trust-model.md), [ADR-0033](../adr/0033-transactional-write-pattern.md)). |
| PT-003 | linking | A hard link inside the allowlist shares an inode with a file reachable only through a path outside it, linking content the operator granted to content they did not. | inode identity surfaced by `fs.stat`; file bytes returned by `fs.read` | [ADR-0035](../adr/0035-path-safety-hardening.md) specifies an `nlink > 1` WARN on `fs.stat` and `fs.read` plus the opt-in `security.reject_hardlinks` key, which exists in the config model. Residual: no code reads `nlink` yet and nothing enforces `reject_hardlinks`, so the default is silent ([ADR-0029](../adr/0029-threat-model.md)). |
| PT-004 | identifying | `sys.hostname`, `sys.uname` and `sys.info` hand the model a stable machine fingerprint — hostname, kernel release, build version, machine architecture — that survives across sessions and re-identifies the host each time. | hostname; `sysname`, `nodename`, `release`, `version`, `machine`; kernel summary | The values come straight from `gethostname(2)` and `uname(2)` and are not pseudonymised, and outbound network is off by default, so the fingerprint stays on the machine until the model forwards it ([ADR-0020](../adr/0020-telemetry-opt-out.md)). |
| PT-005 | identifying | `proc.list` and `proc.tree` return the full space-joined command line of every process, so a secret passed on argv — `--token=…`, `-pPASSWORD`, a connection string — reaches the model, and the `uid`/`gid` fields identify the owning account. | `ProcessInfo::command` (full argv), `uid`, `gid` | The command line is read best-effort per platform (`/proc/<pid>/cmdline` on Linux, `KERN_PROCARGS2` on macOS) and returned verbatim. Residual: no argv-aware redaction exists, so an argv secret is disclosed by design ([ADR-0029](../adr/0029-threat-model.md)). |
| PT-006 | non-repudiation | The audit trail is not guaranteed complete: events are dropped under back-pressure, so a tool call can have happened with no record and no way to prove it did. | the audit stream itself: `tool`, `outcome`, `error_code`, `seq` | [ADR-0009](../adr/0009-observability.md) specifies a non-blocking writer with a `lost_lines` counter and a WARN line at shutdown when it is non-zero, and makes monitoring that field an operator obligation. Residual: the shipped `logging::init` installs a plain blocking stderr writer, so nothing counts drops today. |
| PT-007 | non-repudiation | Fields the audit stream records as fact are caller-asserted: `elicitation_confirmed` is a boolean the caller sets, and `client_id` is the client's own `clientInfo.name` after sanitisation, so a prompt-injected agent can claim human confirmation and two clients can share one identity. | `elicitation_confirmed`; `client_id` | An absent confirmation fails closed with `SUBSTRATE_CONFIRMATION_REQUIRED`, and `client_id` is sanitised server-side (non-conforming characters to `_`, truncated to 64, fallback `anonymous`). Residual: the server never runs a real `elicitation/create` round-trip, and that gap is documented at the call site ([ADR-0052](../adr/0052-subprocess-execution-architecture.md), [ADR-0040](../adr/0040-async-job-control-plane.md)). |
| PT-008 | detecting | Activity is inferable without reading a file: the audit stream is the stderr of a client-spawned process, readable by any same-user process, and `net.tcp_list`/`net.udp_list` expose the local socket table including remote peers. | stderr audit lines; local and remote socket addresses and states | Audit records are distinguishable by `target = "substrate.audit"` (ADR-0009 specifies an `audit=true` field for the same purpose), and the socket table is a read-only snapshot. Residual: substrate binds no listener, so nothing gates who may read the sink ([ADR-0009](../adr/0009-observability.md), [ADR-0058](../adr/0058-network-socket-introspection.md)). |
| PT-009 | data-disclosure | A secret embedded in a tool argument reaches stderr in the clear: `fs.*` handlers log the raw argument through `#[instrument(fields(path = %req.path))]`, and no redaction runs on span fields. | raw `path`, `root` and `pattern` span fields; `args_summary` on the audit event | [ADR-0018](../adr/0018-logging-redaction.md) specifies a pre-emit redaction pipeline (pattern families plus CRLF and null normalisation) and a `SecretString` type; what ships is the literal-needle `Redactor` in `substrate-launch`, applied to launch event lines, plus the operator-supplied `security.extra_redaction_patterns`. Residual: neither `SecretString` nor the pattern-family matcher is wired into the `fs.*` path, so an unlisted secret in a path argument is logged verbatim. |
| PT-010 | data-disclosure | `env_file` reads `.env` files out of the profile directory and injects every `KEY=VALUE` into the supervised child, but the values are not treated as secrets: they are never logged, never typed as `SecretString`, and no content denylist applies. | every key and value of each listed `.env` file; the merged child `env_override` | Containment is enforced before the read — the path must be relative, must not contain `..`, and its canonicalised form must stay inside the canonical profile directory — and the merged map passes the same banned-key gate as inline `env`, failing with `SUBSTRATE_SUBPROCESS_ENV_BANNED`. A read or parse failure is a hard `InvalidProfile` error, so a Service never starts with a silently partial environment ([ADR-0071](../adr/0071-launch-env-file-support.md)). |
| PT-011 | data-disclosure | Supervised child output outlives the session: `supervisor.log`, the durable `events.ndjson` event-log and the per-service raw logs are written under the state directory, and `subprocess.result`/`subprocess.search` hand captured stdout and stderr back to the model. | child stdout and stderr lines; `Semantic` event messages; capture files under `subprocess.tmp_root` | Redaction runs at the source: every line is masked through the merged global and per-Service denylist before it reaches the event log or any client ([ADR-0066](../adr/0066-launch-event-stream-and-notification-model.md)), and capture files are created mode `0600` with size-based rotation capped by `keep_files` ([ADR-0056](../adr/0056-subprocess-supervisor-semantics.md)). Residual: the redactor lives in `substrate-launch` and `substrate-subprocess` does not call it, so `subprocess.result` output and the capture files stay raw. |
| PT-012 | unawareness | The operator cannot tell what content left the machine: the audit event records the tool and the path, not the bytes read, so "did the model see my secrets file" is answered only by inference. | file bytes returned by `fs.read` and `text.search`; the model transcript | The `target = "substrate.audit"` record with its `correlation_id` lets a reviewer line a read up against the model transcript, and `fs.hash` yields a blake3 digest that pins which revision was read. Residual: the audit event itself carries no byte count and no content digest. |
| PT-013 | unawareness | Launch redaction is a literal-substring denylist in this MVP: a secret is masked only when its exact value was configured, so an unlisted secret passes silently while the operator believes redaction is on. | child output lines; the `Redactor` needles drawn from the global denylist and the per-Service `redact` list | `Redactor::new` merges both lists, drops empty entries and sorts longest-needle-first, and `Redactor::is_empty()` makes the no-op case observable; the MVP matching strategy is documented in the module. Residual: regex and assignment-shaped patterns are deferred until the pattern grammar is fixed ([ADR-0066](../adr/0066-launch-event-stream-and-notification-model.md)). |
| PT-014 | non-compliance | There is no retention window and no erasure path: `launch.forget` drops only the in-memory registry entry, leaving the trust record and the whole stack directory on disk, and the audit log has no rotation policy. | `launch-trust.toml`; `<state_root>/substrate/stacks/<id>/` holding `supervisor.json`, `supervisor.log` and the `events.ndjson` event-log | The stack directory is created mode `0700` and `supervisor.json` is written atomically at mode `0600` after ancestor-directory validation, and state is rooted at `${XDG_STATE_HOME:-~/.local/state}` so an operator can delete a tree deliberately. Residual: `forget` is not an erasure operation, and the retention cross-reference in [ADR-0018](../adr/0018-logging-redaction.md) points at [ADR-0009](../adr/0009-observability.md), which defines no window. |

## Observability

A privacy control that fails has to be visible without reading source. The
redaction unit tests in `substrate-launch/src/redaction.rs` and the cucumber steps
in `crates/substrate-mcp-server/tests/steps/launch/events.rs` assert that a
configured needle is replaced by `[REDACTED]` in both the stored event and the
delivered event, so a denylist regression fails the suite instead of leaking
quietly. At runtime, audit records are distinguishable on stderr by
`target = "substrate.audit"` (ADR-0009 specifies an `audit=true` field for the
same filtering purpose), and reading that stream against a session's
`correlation_id` shows which paths were touched and which client claimed the call.
The rows above that name no closing control — the literal denylist, the unredacted
`path` span fields, the unredacted `subprocess.result` output — are the residual
risks an operator accepts explicitly rather than risks this document claims to
have solved.
